# 5차 — UI 디자인 검수 기록

## 진행 방식

1. 프레임 목업 — 승인 완료
2. UI 의사결정 — 진행 중
3. 테마 선택

이번 단계부터 구현물을 검수하고 피드백에 따라 반복 수정한다.

## 기술 결정

- Next.js 16
- React 19
- Tailwind CSS 4
- shadcn/ui
- Lucide 아이콘
- 모바일 우선

## 검수 1 — 프레임 목업

- 상태: 1차 검수 승인 및 피드백 반영 완료
- 테마: shadcn 기본 테마
- 검수 범위: 정보 우선순위, 화면 이동, 빠른 행동, 화면별 목적
- 검수 제외: 브랜드 컬러, 최종 서체, 장식적 그래픽, 애니메이션 완성도

### 구현 화면

- 할 일
- 영업판
- 영업 건 상세
- 영업 건 직접 추가
- 계약·청구
- 성과
- 회사 검색
- 관리

### 검수용 프레임 결정

- 하단의 5개 주 영역: 할 일, 영업판, 계약·청구, 성과, 관리
- 회사는 상단 검색과 관리 영역에서 접근하는 보조 정보
- 할 일은 `내 담당 / 전체` 전환 후 기한 초과를 가장 먼저 노출
- 영업판은 큰 단계를 먼저 선택하고 영업 건 카드로 세부 내용을 확인
- 영업 건 카드에서 전화·완료·위임을 빠르게 실행
- 영업 건 상세는 현재 상태 → 고객 정보 → 다음 행동 → 활동 이력 → 문서·계약 순서
- 계약·청구와 성과는 운영 화면과 판단 화면으로 분리

### 자동 검수

- lint 통과
- TypeScript 검사 통과
- 단위 스모크 테스트 통과
- Next.js 운영 빌드 통과
- 모바일 브라우저 E2E 및 핵심 8개 화면 접근 확인

### 리뷰 기록

#### 1차 검수

- 할 일 화면의 정보 순서 승인
- 하단 5개 주 영역 승인
- 영업판의 단계 요약과 영업 건 목록 구성 승인
- 카드의 전화·완료·위임 빠른 행동 승인
- 추가 요청: 영업 건 카드에서 초기 요청 내용을 한 줄로 미리보기
- 반영: 회사명과 담당자 아래에 `초기 요청 · 한 줄 요약`을 표시하고 긴 내용은 한 줄 말줄임 처리

#### 전체 화면 범위 확장

- UI 의사결정 단계 진입을 보류하고 전체 업무 화면을 먼저 프레임 목업으로 확장
- 대표 화면 8개에서 실제 업무 완료에 필요한 46개 화면으로 범위 확대
- 모든 임시 링크를 상세·등록·수정·승인·관리 화면에 연결
- `/frames`에 영역별 전체 화면 검수 인덱스 추가
- 46개 경로의 HTTP 응답, 화면 제목, 모바일 가로 넘침 자동 검사
- 각 화면의 전체 길이 스크린샷을 `artifacts/frames`에 생성
- 영역별 비교 검수 시트를 `artifacts/review-sheets`에 생성
- 시각 검수 중 청구 상태와 맞지 않는 빠른 행동을 발견해 `발행 예정 → 발행`, `입금 대기·미수금 → 입금`으로 수정

### 전체 프레임 검수 게이트

다음 항목이 사용자에게 승인되기 전에는 UI 의사결정 단계로 넘어가지 않는다.

1. 화면 누락 여부
2. 화면별 핵심 목표와 정보 범위
3. 이전·다음 화면 이동 경로
4. 상태별 핵심 행동
5. 등록·수정·승인·예외 처리 흐름
6. 모바일 정보 밀도와 스크롤 길이

사용자가 UI 의사결정 단계로의 진행을 승인했으므로 전체 프레임 목업 범위는 46개 화면으로 잠근다. 이후 변경이 필요하면 화면 누락 보완이 아닌 변경 요청으로 기록한다.

## UI 의사결정 — 1차 검수

테마 선택 전에 다음 전역 규칙을 결정한다.

1. 정보 밀도: 여유형 카드 권장
2. 저장 방식: 중요 입력은 명시적 저장, 단순 행동은 즉시 반영
3. 화면 전환: 복잡한 입력은 전체 화면, 단일 선택·확인은 하단 시트
4. 행동 위계: 화면당 핵심 채움 버튼 1개
5. 상태 피드백: 빨강은 지연·오류·위험에만 사용
6. 금액 표현: 입력·상세는 원 단위, 목록·성과는 만원·억원 단위

검수 화면은 `/ui-decisions`에서 확인한다.

### 1차 검수 표현 방식 수정

- 사용자 피드백: 여섯 가지 결정을 문장 설명이 아닌 실제 UI 예시로 비교할 것
- 반영: 각 결정에 동일 업무 맥락의 권장안·대안 화면을 구현
- 정보 밀도: 여유형 영업 카드와 압축 목록 비교
- 저장 방식: 명시적 계약 저장과 즉시 자동 저장 비교
- 화면 전환: 계산서 전체 화면과 담당자 선택 하단 시트의 적용 맥락 비교
- 행동 위계: 핵심 버튼 1개와 모든 버튼 동일 강조 비교
- 상태 피드백: 의미 제한 상태색과 단계별 다색 배지 비교
- 금액 표현: 정확 입력과 요약 단위 전환을 동일 데이터로 비교

### UI 의사결정 확정

- 정보 밀도: A안, 여유형 영업 카드
- 저장 방식: A안, 중요 입력은 명시적 저장
- 화면 전환: 권장 혼합 규칙, 복잡한 입력은 전체 화면·단일 선택은 하단 시트
- 행동 버튼 위계: A안, 화면당 핵심 행동 1개
- 상태 피드백: A안, 빨강은 지연·오류·위험에만 사용
- 금액·날짜 표현: A안, 입력·상세는 정확 단위·목록과 성과는 요약 단위

사용자가 권장안을 승인했으므로 UI 의사결정 단계를 완료하고 테마 선택 단계로 전환한다.

## 테마 선택 — 완료

테마는 브랜드 인상, 실제 사용 환경, 기존 브랜드 자산, 강조색과 경고색의 관계, 서체와 정보 밀도를 기준으로 후보를 만든다. 인터뷰 답변을 바탕으로 실제 CRM 화면에 적용한 복수 후보를 비교한 뒤 선택한다.

### 테마 인터뷰 1차

- 핵심 인상: 전문성
- 기존 브랜드 자산: 첨부된 바이브코딩대학 웹사이트 화면 2개
- 브랜드 노출 강도: 적당히
- 주요 사용 환경: 이동 중 모바일
- 선호·회피 색상: 별도 제약 없음
- 글자 인상: 단정하고 중립적

### 첨부 시각 자산에서 추출한 방향

- 대표색: 채도가 높은 코발트 블루
- 기본 면: 흰색과 매우 옅은 중립 회색
- 기본 글자: 검정에 가까운 고대비 색상
- 타이포그래피: 굵은 제목과 명확한 크기 대비
- 형태: 각이 분명한 버튼·박스와 넉넉한 여백
- CRM 적용 원칙: 브랜드 블루를 전체 배경보다 핵심 행동, 선택 상태, 포커스에 제한해 전문성과 이동 중 가독성을 함께 확보
- 위험색: 기존 UI 결정에 따라 빨강을 지연·오류·위험 전용으로 보존

### 테마 인터뷰 2차

- 제품 표시명: 트루노스크루
- 브랜드 블루 범위: 주요 버튼·선택 상태·링크로 제한
- 기본 바탕: 옅은 회색 바탕과 흰색 카드
- 다크 모드: 첫 버전에서 제외
- 서체: Pretendard 승인

### 확정 기반 테마 — 트루노스크루 프로페셔널 코발트

- 대표색은 첨부 이미지에서 추출한 `#0047FF`
- 기본 바탕은 첨부 이미지에서 추출한 `#F4F5F6`
- 카드·헤더·하단 내비게이션은 흰색
- 본문은 검정에 가까운 중립색, 보조 문자는 회색
- 빨강은 기한 초과·오류·위험 행동에만 사용
- Pretendard Variable을 애플리케이션에 포함해 외부 CDN 없이 제공
- 라이트 테마만 지원해 이동 중 모바일 가독성과 구현 완성도에 집중
- 검수 경로: `/theme-preview`

### 글래스모피즘 확장 — 절제형 코발트 글래스

사용자가 권장 전략의 구현을 승인해 기존 프로페셔널 코발트 위에 절제형 글래스 시스템을 추가한다.

- 적용 강도: B, 절제형 업무용 글래스
- 배경: `#F4F5F6` 위에 낮은 불투명도의 코발트·하늘색 광원 각 1개
- 일반 요약 표면: 흰색 82%, 블러 18px
- 고정 헤더·내비게이션: 흰색 88%, 블러 24px
- 고객·기한·금액이 있는 업무 카드: 흰색 95%, 블러 6px
- 주요 행동: 불투명 `#0047FF` 유지
- 지연·오류·위험: 불투명 빨강 유지
- 적용 대상: 헤더, 하단 내비게이션, 범위 필터, KPI 요약, 성과 요약, 바텀시트·팝업
- 제한 대상: 입력 폼, 계약·계산서, 긴 본문, 촘촘한 영업 데이터
- 미지원 브라우저: 97% 흰색 표면으로 자동 대체
- 투명도 감소 환경: 블러를 제거하고 97% 흰색 표면으로 전환
- 검수 경로: `/theme-preview`
- 검수 당시 적용 범위: 검수 화면에만 제한

### 테마 최종 확정 및 전체 적용

사용자가 절제형 코발트 글래스 스타일을 최종 확정했다. 검수 전용 클래스를 전체 애플리케이션의 공통 셸로 승격하고 다음을 적용한다.

- 전체 46개 업무 화면과 로그인 화면에 프로페셔널 코발트 토큰 적용
- 전체 화면 배경에 옅은 코발트·하늘색 광원 적용
- 공통 화면 헤더와 모바일 하단 내비게이션에 강한 글래스 표면 적용
- 담당 범위 필터와 KPI 요약에 일반 글래스 표면 적용
- 고객·계약·계산서·입력 영역은 95% 흰색의 업무 데이터 표면 적용
- 주요 행동은 불투명 코발트, 지연·오류·위험은 불투명 빨강 유지
- `FRAME MOCKUP · SHADCN DEFAULT` 검수 표식을 실제 애플리케이션에서 제거
- 브라우저 UI 색상을 기본 배경 `#F4F5F6`로 통일
- `/theme-preview`는 확정된 디자인 시스템의 참조 화면으로 유지

피드백과 반영 결과는 반복 차수별로 이 문서에 계속 누적한다.
