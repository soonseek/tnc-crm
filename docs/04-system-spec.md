# 4차 — 시스템 구조·기능 명세

## 구조

- 배포: Railway 싱가포르 리전
- 코드: GitHub 모노레포
- 환경: PR 검토, 스테이징, 운영 분리
- 실행 서비스: Web, API, Worker, Cron
- 데이터: PostgreSQL
- 작업 대기열: Redis
- 인증: 회사 Google Workspace
- 문서: Google Drive 링크
- 이메일: Gmail 발신 전용 계정

Emergent는 상담 접수와 텔레그램 알림을 독립적으로 처리한다. CRM은 Webhook으로 신규 문의를 거의 즉시 받고 5분마다 API로 누락을 복구한다. CRM 장애가 상담 접수에 영향을 주지 않아야 한다.

## CI/CD

- GitHub는 코드 이력과 `develop`·`main` 릴리스 기준점으로 사용
- GitHub Actions는 계정 Billing 제한으로 자동 실행하지 않음
- 로컬에서 lint, typecheck, test, build를 통과한 커밋만 PR로 병합
- `develop`: 검증 후 스테이징 수동 배포
- `main`: PR 병합 시 Railway에 직접 연결된 운영 API·Web 자동 배포
- DB 변경은 배포 전 실행하고 실패 시 배포 중단
- 배포 후 상태 점검 실패 시 이전 버전 유지

## API

- REST·JSON, `/api/v1`, OpenAPI
- UTC 저장·KST 표시
- 커서 페이지 처리
- API 계정별 분당 120회, 일괄 100건
- 쓰기·재무·일괄 요청은 중복 방지키 사용
- 완전 삭제 대신 보관·취소
- 외부 API 구버전 최소 6개월 유지

### 권한

- 관리자: 전체 조회·수정·승인
- 열람자: 재무 포함 전체 읽기
- AI 서비스 계정: 발급된 범위만 사용

회사 Google 계정은 인원 제한 없이 열람자로 즉시 가입하며 관리자가 역할을 변경한다. AI는 영업 정보를 직접 반영할 수 있지만 계약·계산서·입금·환불 변경은 기본적으로 관리자 승인을 거친다.

## 배치

- Emergent 누락 조회: 5분마다
- 장기 미활동 검사: 매일 업무 시작 전
- 업무 시작 알림: 업무일 오전 9시
- 첫 연락 지연 알림: 업무일 오후 3시
- 계산서 발행: 3업무일 전과 당일 오전 9시
- 다음 행동: 당일 오전 9시, 지연 시 매일
- 미수금: 업무일 오전 9시 전체 사용자
- AI 승인: 즉시 및 미처리 시 매일 오전 9시
- 중단 중 놓친 작업: 복구 후 재실행

휴가는 CRM에 직접 등록하며 휴가 중 새 상담만 대체 담당자에게 자동 위임한다. 휴가 종료 후에도 대체 담당자가 계속 담당한다.

## 외부 연동

- Emergent: HMAC 서명 Webhook·조회 API
- Google 로그인: OpenID Connect
- Gmail: 발신 전용 계정
- Drive: 링크만 저장하고 권한은 Drive에서 관리
- 공휴일: 한국천문연구원 특일 정보 API
- AI: 서비스 계정 API와 HMAC Webhook
- 배포 인증: production은 Railway GitHub 연결, staging 수동 배포는 운영 담당자의 Railway CLI 로그인
- 장애 알림: 관리자 설정의 보조 이메일·범용 Webhook
- 텔레그램: 기존 Emergent 기능 유지

## 안정성

- 최대 중단 허용: 반나절
- 허용 데이터 손실: 최대 하루
- 매일 백업, 주간·월간 보관, 분기별 복원 시험
- 잘못된 외부 데이터는 검토 필요 보관함으로 격리
- 고유 원본 ID, 중복 방지키, 분산 잠금, 배치 실행 이력
- 실패 작업 최대 5회 재시도 후 실패 보관함
- Google 인증 자동 갱신 및 실패 시 재로그인
- Gmail 장애는 별도 채널로 통보
- 영업·계약·계산서·감사 기록은 계속 보관
